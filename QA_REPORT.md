## 1. Карта системы

### 1.1 Стек и структура

| Слой | Технология | Где |

| Frontend | Next.js 14.2.5 (App Router), React 18, Leaflet, axios, zustand | `frontend/` |

**Запуск** (по `README.md`): `cd backend && pip install -r requirements.txt` → `.env` из `.env.example` → `python main.py` (Flask :5000); `cd frontend && npm install && npm run dev` (:3000; `/api/*` проксируется на Flask через `next.config.js`); бот: `python backend/telegram_bot/bot.py`.
**Тесты:** backend на pytest (`backend/tests/`, 15 файлов; по `docs/validation.md` 118 passed на 15.10), frontend на Jest (4 сьюта, 13 тестов), есть `tsc --noEmit` и `next lint`.

### 1.2 Реальный поток (как в коде, а не как в ТЗ)

```
Регистрация (сайт) → привязка Telegram: пользователь ВРУЧНУЮ вводит свой Telegram ID (без проверки)
→ заявка (сайт /api/applications или бот /create) → статус PENDING
→ админ одобряет (/api/admin/applications/<id>/approve)
   → ТОЛЬКО ТОГДА: notify_matching → уведомления волонтёрам с is_available=True,
     тем же city (точное совпадение) и всеми нужными capabilities
→ волонтёр откликается (ТОЛЬКО через сайт; в боте отклика нет)
→ автор принимает отклик → автор завершает заявку → рейтинг
```

**Расхождения с описанием продукта** `[КОД]`:
- Ни заявка, ни **SOS** не попадают на карту и не рассылаются волонтёрам сразу: сначала нужна модерация. SOS тоже остаётся в `PENDING` (`views.py:2717`, `common.py:192`). Админам о новых SOS никто не сообщает: в коде нет уведомлений с `isAdmin=True`.
- «Волонтёр откликается и получает локацию» в боте не реализовано: хендлеров отклика нет (`bot.py:36-66`). В уведомлении `new_request` только текст без координат (`community.py:227-232`).
- Принять можно только одного волонтёра: `accept_response` отменяет ранее принятых (`views.py:1960-1973`). Это противоречит `docs/scope-october-2026.md` («The author accepts several helpers»).

## 6. Регрессионная стратегия

**Smoke на каждый релиз** (≤ 10 мин, сначала руками, потом Playwright):
1. Регистрация → логин → логаут.
2. Создать заявку с фото → админ одобряет → заявка на карте.
3. Волонтёр откликается → автор принимает → завершает → ставит оценку.
4. SOS с сайта (геолокация замокана) → виден в админке.
5. Бот: `/start`, `/create` → гео, `/sos`, `/resources`.
6. Уведомления: колокольчик на сайте + 1 сообщение в TG тест-чат.
7. `/api/uploads` медиа одобренной заявки открывается, медиа pending-заявки возвращает 403.

**P0-набор** в CI на каждый PR: T-01…T-10 + существующие `test_security.py`, `test_contract_regressions.py`, `test_full_stack_contract.py`.
